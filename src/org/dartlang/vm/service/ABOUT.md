# vmServiceDrivers Service

## Overview
Provides the main Dart VM Service client implementation, including the `VmService` class and related listeners for interacting with a running Dart VM via JSON-RPC.

## Interface
- [`RemoteServiceCompleter`](RemoteServiceCompleter.java) (interface) - Interface to be called when a service request completes successfully or with an error.
- [`RemoteServiceRunner`](RemoteServiceRunner.java) (interface) - Interface used by VmService to register callbacks to services, handling incoming requests.
- [`VmService`](VmService.java) (class) - Main public class representing the Dart VM Service client. Generated by `pkg/vm_service/tool/generate.dart` in dart-lang/sdk; do not hand-edit. Provides:
  - Connection via the inherited static `connect(String url)` and the deprecated `localConnect(int port)` (which calls `connect("ws://localhost:<port>/ws")`).
  - A comprehensive set of typed RPC methods (e.g., `addBreakpoint`, `evaluate`, `getIsolate`, `resume`).
  - Stream ID constants (`DEBUG_STREAM_ID`, `EXTENSION_STREAM_ID`, `GC_STREAM_ID`, `ISOLATE_STREAM_ID`, `LOGGING_STREAM_ID`, `STDOUT_STREAM_ID`, `VM_STREAM_ID`, ...) and the supported protocol version (`versionMajor`/`versionMinor`).
- [`VmServiceBase`](VmServiceBase.java) (package-private abstract class, implements [`VmServiceConst`](internal/VmServiceConst.java)) - Hand-written, non-generated base of `VmService`. Handles connection management, WebSocket listeners, and JSON-RPC dispatching. Public APIs inherited by `VmService`:
  - `addVmServiceListener`/`removeVmServiceListener`, `addServiceRunner`/`removeServiceRunner`
  - `getRuntimeVersion()`, `disconnect()`
  - `callServiceExtension(isolateId, method, consumer)` and an overload taking a `JsonObject params`
  - `getInstance`/`getLibrary`, which wrap the abstract `getObject` and report an `RPCError.unexpected` error on a type mismatch
- [`VmServiceListener`](VmServiceListener.java) (interface) - Interface used to notify clients of VM connection state changes and incoming stream events.
- `consumer`: [./consumer/ABOUT.md](./consumer/ABOUT.md) - Consumer callback interfaces (e.g. AddBreakpointConsumer, InvokeConsumer).
- `element`: [./element/ABOUT.md](./element/ABOUT.md) - Data model elements (e.g. AllocationProfile, Breakpoint, Event, Instance).
- `internal`: [./internal/ABOUT.md](./internal/ABOUT.md) - Internal network sinks and WebSocket clients.
- `logging`: [./logging/ABOUT.md](./logging/ABOUT.md) - Logger interface and global Logging configuration.

## Invariants
- `VmService` is not thread-safe and must only be accessed from a single thread.
- A given Dart VM instance should only be accessed from a single instance of `VmService`.
- Calls to `VmService` should not be nested; specifically, calls to `VmService` should not be made from within any `Consumer` callback method.
- `connect` accepts only `ws`/`wss` URLs (otherwise it throws `IOException`). After opening the socket it blocks on a `getVersion` handshake for up to 5 seconds, stores the result as `runtimeVersion`, and throws `IOException` on timeout or error.
- A thread-safe atomic counter (`nextId`) generates unique IDs for all outgoing JSON-RPC requests.
- A mapping (`consumerMap`) routes incoming JSON-RPC responses back to the initiating `Consumer`. `request()` writes it under `consumerMapLock`, but `processResponse` removes entries without taking the lock.

## Side Effects
- Establishes and maintains a persistent WebSocket connection to the Dart VM Service.
- Mutates the running state of the target Dart VM (e.g., adding/removing breakpoints, pausing/resuming execution, evaluating expressions).
- Notifies registered `VmServiceListener` instances synchronously on the WebSocket callback thread, iterating over a copy of the listener list. Exceptions thrown by a listener are logged and do not stop delivery to the others.
- Executes `RemoteServiceRunner` callbacks when extension requests are received.
- Logs connection lifecycle events and errors to the globally configured Logging system.
